## 1. Продукт в одном абзаце

ПИНОК — мобильное веб-приложение (PWA), где у пользователя есть несколько AI-тренеров
с сильными характерами. Интерфейс выглядит как мессенджер: список чатов с тренерами,
переписка, голосовые сообщения и ВИДЕОЗВОНОК, КОТОРЫЙ И ЕСТЬ ТРЕНИРОВКА. Во время звонка
тренер через камеру телефона видит каждое движение, считает повторения, ругает за плохую
технику и лень, реагирует голосом в реальном времени. Тренер помнит прошлые тренировки,
сам пишет первым и может обидеться и НЕ ОТВЕЧАТЬ, если ты пропустил тренировку.
Прогресс измеряется не уровнями, а отношением тренера к тебе: Презирает → Терпит →
Уважает → Гордится. После тренировки приложение само собирает смешной 10–15-секундный
клип для TikTok/Reels — это главный двигатель роста.

Чем мы НЕ являемся: не скучный трекер с уровнями, не обучающее приложение в стиле
Duolingo, не мультяшный продукт, не AI-друг или «вторая половинка».

## 2. Аудитория и тон

- Основная аудитория: 16–30 лет, смотрят gym- и фитнес-контент в TikTok, тренируются дома
  без тренера. Минимальный возраст пользователя — 13 лет (см. раздел 13).
- Тон: дерзкий, смешной, жёсткий, но НИКОГДА не жестокий. Тренер ругает технику и лень,
  а не человека. Юмор — в словах, а не в картинке. Визуально продукт серьёзный и чистый.
- Язык интерфейса v1: русский. Все строки — через файл локализации (/locales/ru.json),
  чтобы позже добавить английский и другие языки без переписывания кода.

## 3. Технический стек (не меняй без согласования)

- Фреймворк: Next.js (App Router) + TypeScript — один проект для фронта и серверных API.
- Стили: Tailwind CSS с токенами из раздела 5.
- Приложение: PWA (manifest, service worker, установка на главный экран) — без App Store на старте.
- Распознавание позы: @mediapipe/tasks-vision → PoseLandmarker в браузере — бесплатно,
  на устройстве, видео никуда не уходит.
- База, вход, файлы: Supabase (Postgres + Auth + Storage + Row Level Security).
- Нейросеть для чата: Anthropic API через @anthropic-ai/sdk, только из серверных роутов.
  Модель по умолчанию claude-haiku-5-5, для недельных итогов claude-sonnet-5-5.
  ID моделей вынеси в конфиг и сверь с актуальной документацией docs.claude.com.
- Голос тренера: ElevenLabs TTS только с сервера, с кэшированием в Supabase Storage.
- Распознавание речи: v1 — Web Speech API в браузере (push-to-talk). Если браузер не
  поддерживает — кнопка «написать текстом». Позже — серверный STT.
- Уведомления: Web Push (библиотека web-push, VAPID-ключи) + расписание через
  Supabase Cron / Edge Functions.
- Клипы: MediaRecorder + <canvas> с наложением субтитров, без сервера.
- Аналитика: PostHog (бесплатный тариф), без записи видео и без персональных данных в событиях.
- Тесты: Vitest (логика), Playwright (основные экраны).
- Деплой: Vercel.
- Менеджер пакетов — pnpm. Node — актуальная LTS.

## 6. Экраны

### 6.1 Главный экран — «Тренеры» (/chats)

Сверху вниз:
1. Шапка: логотип «ПИНОК» слева; справа две кнопки-иконки 44px (Поиск, Настройки) на --surface.
2. Заголовок «Тренеры».
3. Карточка-герой (фон --accent, белый текст): «СЕГОДНЯ · 18:00», название тренировки
   («Ноги. 20 минут.»), фраза текущего тренера в его стиле («Громов уже ждёт. Не заставляй
   его звонить первым.»), аватар тренера справа, внизу чип «Серия N дней» с иконкой огня
   и белая кнопка-пилюля «Позвонить» (видеокамера + текст).
   Если тренировки сегодня нет — карточка предлагает ближайшую или «Свободная тренировка».
4. Заголовок секции «ПЕРЕПИСКИ» и счётчик «N тренера».
5. Список чатов. Каждая строка: аватар (+ индикатор «в сети»), имя, бейдж отношения,
   превью последнего сообщения, время, счётчик непрочитанных.
   - Если последнее сообщение моё и тренер игнорирует: двойная галочка «прочитано» + «Вы: …»,
     справа серое «без ответа».
   - Если последнее — голосовое: иконка микрофона + «Голосовое · 0:14».
   - Строка с непрочитанными выделена фоном --surface, время цвета --accent.
6. Заблокированный слот: пунктирный круг (2px dashed #A9B8D6) с замком, «Новый тренер»,
   условие разблокировки («Откроется, когда Громов начнёт тебя уважать»).
7. Нижняя навигация.

Сортировка: сначала чаты с непрочитанными, потом по времени последнего сообщения.
Моковые данные для разработки: Громов — «Презирает», 3 непрочитанных, «Ты где был вчера?
В 18:00 жду. Опоздаешь — пожалеешь.», 07:12; Марина — «Игнорирует», «Вы: Прости, завтра
точно приду», Вчера, без ответа; Палыч — «Терпит», голосовое 0:14, Пн, 1 непрочитанное;
Макс — «Уважает», «Целых 8 отжиманий. Рекорд века, поздравляю.», 12 окт.

### 6.2 Чат с тренером (/chat/[coachId])

1. Шапка: «назад», аватар 44px, имя, статус цвета --accent («в сети · ждёт тебя»,
   «был(а) 3 часа назад», «занят, тренирует нормальных людей» и т.п.), круглая синяя
   кнопка видеозвонка 46px.
2. Блок «ОТНОШЕНИЕ»: подпись, название текущего уровня (Unbounded 800, цвет бейджа),
   шкала из 4 сегментов (текущий частично заполнен), подписи уровней под сегментами,
   строка-подсказка: «Ещё 3 тренировки без пропусков — и он начнёт тебя терпеть».
3. Лента: плашки дат («Вчера», «Сегодня»), входящие белые пузыри с рамкой --line,
   свои — синие, со статусом «прочитано» (две галочки). Голосовые сообщения: синяя кнопка
   Play, волна из столбиков (проигранная часть --accent, остальное --wave-rest),
   длительность и время.
4. Карточка тренировки в ленте (рамка 2px --accent): иконка, «Тренировка: ноги»,
   «Сегодня, 18:00 · 20 минут · камера», кнопка «Начать звонок».
5. Поле ввода: кнопка «+», поле с плейсхолдером в характере тренера («Оправдывайся тут…»),
   кнопка записи голосового. Плейсхолдер — свой у каждого тренера.
6. Индикатор «печатает…» и «записывает голосовое…» в шапке, когда тренер отвечает.
   Реалистичная задержка ответа (1–4 секунды на «печатание», зависит от длины).

Моковая переписка с Громовым: Вчера 18:07 «18:00 прошло. Я стоял с секундомером, как дурак.
Где ты?»; 19:30 «Молчишь. Понятно.»; Сегодня 07:05 (моё) «Прости, был занят»; 07:11
голосовое 0:14; 07:12 «Занят он. Сегодня в 18:00 — ноги. Опоздаешь — плюс 10 приседаний
за каждую минуту.»; затем карточка тренировки.

### 6.3 Видеозвонок = тренировка (/call/[sessionId])

Полноэкранная камера, минималистичный оверлей в стиле спортивной трансляции:
- Сверху: маленький аватар тренера в кружке (меняет эмоцию), имя, таймер.
- По центру сверху — большой счётчик повторений (Unbounded 800, белый с тенью).
- Снизу — субтитры фразы тренера (крупный жирный шрифт, белый на полупрозрачной
  тёмно-синей плашке rgba(11,27,63,0.7)), чтобы клип был понятен без звука.
- Индикатор качества техники текущего повтора (зелёный/жёлтый/красный — различимый
  не только цветом: SVG-иконки галочки, восклицательного знака и крестика).
- Кнопки: пауза, микрофон (push-to-talk — «сказать тренеру»), завершить.
- Скелет позы — по умолчанию выключен (включается в настройках для отладки).

Перед стартом — экран настройки камеры: «Поставь телефон на пол у стены, отойди на 2–3 метра,
чтобы было видно тебя целиком». Живая проверка: пока всё тело не в кадре, тренер ворчит
(«Я вижу только твою голову. Я тренирую ноги, а не уши»). Старт только когда видны
ключевые точки (плечи, бёдра, колени, щиколотки) с уверенностью ≥ 0.6 в течение 1.5 секунд.

Структура тренировки: разминка → основная часть (подходы) → «добивание» → вердикт.
План тренировки — данные (JSON), а не код.

### 6.4 Результат (/result/[sessionId])

- Вердикт тренера (текст + голос), эмоция-аватар.
- Цифры: повторения, «чистые» повторения в %, время, лучшая серия.
- Анимация изменения шкалы отношения (+N очков, переход уровня — отдельный праздничный момент).
- Клип (раздел 12): превью, кнопки «Поделиться» и «Сохранить». Клип не загружается
  на сервер без явного согласия.

### 6.5 Онбординг — «Первая встреча» (/onboarding)

Сначала магия, потом анкета:
1. Короткое приветствие тренера по умолчанию (Громов) голосом + текстом.
2. «Покажи 10 приседаний. Посмотрим, что ты из себя представляешь». Запрос доступа к камере
   с объяснением, что видео не покидает телефон.
3. Мини-тренировка на 10 приседаний с живыми реакциями.
4. Вердикт («Это было позорно, но я видел хуже»).
5. Только теперь анкета — в виде переписки с тренером, а не формы:
   имя → возраст (13+, раздел 13) → цель (сила / похудение / выносливость / просто форма) →
   сколько минут в день → когда удобно тренироваться → жёсткость (раздел 7.4) →
   выбор тренера (по умолчанию Громов) → разрешение на уведомления в характере
   («Разреши мне писать тебе. Поверь, тебе это нужно»).
6. Регистрация (Supabase Auth: email-ссылка, Google; гостевой режим с последующей привязкой).
   Данные анонимного онбординга переносятся в аккаунт.

### 6.6 Вкладки «Тренировки», «Рейтинг», «Профиль»

- Тренировки: расписание на неделю, история (дата, тренер, упражнения, % чистых повторов),
  каталог упражнений, свободная тренировка.
- Рейтинг: друзья (по ссылке-приглашению), недельный рейтинг по «чистым» повторениям,
  дуэли («кто сделает больше чистых приседаний за 60 секунд», асинхронно: каждый
  выполняет у себя, результат сравнивается). Тренер комментирует результаты друзей.
- Профиль: имя, цели, расписание, жёсткость, голос вкл/выкл, уведомления (частота,
  тихие часы), язык, приватность, экспорт и удаление данных, выход.

## 7. Тренеры

### 7.1 Персонажи v1

Каждый тренер — папка content/coaches/<id>/ с файлами persona.md (характер, манера речи,
запретные темы, 20 примеров реплик), phrases.json (банк фраз, раздел 9), avatar/*.svg,
voice.json (ID голоса ElevenLabs, скорость, стиль).

- gromov — Сержант Громов. Армейский сержант, громкий, короткие рубленые фразы, всё считает.
  Ругает: «Это не присед, это ты в туалет садишься». Хвалит (редко): «…Неплохо. Не зазнавайся».
- marina — Марина Лёд. Холодный профессионал, говорит мало и тихо, ледяной сарказм, мастер игнора.
  Ругает: «Интересно. Ты считаешь это повторением?». Хвалит: «Приемлемо.» (и это высшая похвала).
- palych — Дед Палыч. Ворчливый старый тренер, «вот в наше время», любит слать голосовые.
  Ругает: «Я в 70 лет ниже приседаю, внучок». Хвалит: «Ну, молодец. Почти как я в молодости».
- max — Бро Макс. Фитнес-блогер, пассивная агрессия, фальшивый энтузиазм, сарказм.
  Ругает: «Целых 8! Рекорд века, поздравляю». Хвалит: «Окей, это было реально мощно, бро».

Общие правила всех персонажей — раздел 13. Персонажи НИКОГДА не флиртуют, не изображают
романтические отношения и не говорят пользователю, что он им нужен как друг.
Они тренеры, и всё.

Новые тренеры разблокируются: второй — при уровне «Терпит» с первым, третий — при «Уважает»
с любым, четвёртый — серия 14 дней. (Позже часть тренеров уйдёт в платную подписку.)

### 7.2 Отношение (детерминированный движок, НЕ нейросеть)

Отношение каждого тренера к пользователю — число score от 0 до 100. Нейросеть его
НЕ меняет и НЕ придумывает: она только получает текущий уровень как контекст.
Код — чистые функции в lib/relationship/ с тестами.

Уровни: Презирает 0–24; Терпит 25–49; Уважает 50–79; Гордится 80–100.

События (стартовые значения, вынеси в конфиг):
- Тренировка завершена: +6
- ≥ 80% чистых повторений: +3 сверху
- Личный рекорд: +2
- Тренировка в запланированное время (±30 мин): +1
- Серия 7 дней: +5 разово
- Тренировка брошена на середине: −3
- Пропуск запланированной тренировки: −8
- Каждый следующий день без тренировки: −2
- Извинение в чате: 0 (тренер не верит словам — только делу)

Потолок прироста — не более +15 в сутки (защита от накрутки). Уровень вниз падает
не мгновенно, а с «буфером» 3 очка, чтобы не дёргался туда-сюда.
Подсказка под шкалой считается из конфигурации: сколько тренировок нужно до следующего уровня.

### 7.3 Состояние «Игнорирует» (главная механика)

- Если пропущена запланированная тренировка, тренер переходит в состояние ignoring
  на 12 часов (Марина — на 24 часа).
- В этом состоянии сообщения пользователя помечаются «прочитано», но ответа нет.
  Через некоторое время может прийти одно холодное сообщение («Я думал, ты серьёзный»).
- Выйти из игнора можно ТОЛЬКО ДЕЛОМ: начать и завершить тренировку. Тогда тренер
  отвечает в характере («Явился. Ладно. Посмотрим»).
- Ограничения: не более 1 холодного сообщения за период игнора; если пользователь пишет
  что-то, похожее на кризис, боль, травму или просьбу о помощи — игнор немедленно
  снимается, и включаются правила раздела 13.
- Если пользователь не появляется 7+ дней, тренер может выложить «статус» (как в WhatsApp):
  «Ищу нового ученика. Старый сдулся». Не чаще раза в неделю.

### 7.4 Жёсткость

Пользователь выбирает при онбординге и меняет в профиле в любой момент:
1. Строгий, но справедливый — подколки мягкие, больше поддержки.
2. Жёсткий — стандарт.
3. Без пощады — максимальный сарказм (доступен только 18+).

Жёсткость влияет на выбор фраз из банка и на системный промпт чата. Границы раздела 13
одинаковы для всех уровней.

## 8. AI-чат с тренером

- Роут POST /api/chat (серверный). Клиент отправляет coachId и текст; сервер сам собирает контекст.
- Контекст для модели:
  - системный промпт = общие правила безопасности (раздел 13) + persona.md тренера
    + жёсткость + язык;
  - карточка пользователя: имя, цель, расписание, минут в день (без лишних личных данных);
  - текущий уровень отношения, состояние (normal / ignoring / proud), серия;
  - сводка последних 5 тренировок (даты, упражнения, % чистых, рекорды, что бросил);
  - последние 20 сообщений переписки;
  - «память тренера»: до 10 коротких фактов, которые пользователь сам рассказал
    («по вторникам футбол», «колено побаливает» — последнее помечается как ограничение
    для плана тренировок).
- Ответ модели — СТРУКТУРИРОВАННЫЙ (через tool use / JSON-схему):
  { "messages": [{ "type": "text" | "voice", "text": "..." }], "emotion": "angry|...",
    "action": null | { "type": "propose_workout", "planId": "..." } | { "type": "remember", "fact": "..." } }
  Валидируй схему; при ошибке — повтор 1 раз, потом безопасная заготовленная фраза.
- Тренер может ответить 1–3 сообщениями подряд, иногда голосовым (не чаще 1 голосового
  из 4 ответов — экономия).
- Тренер может САМ писать первым (утреннее задание, напоминание, реакция на пропуск) —
  это тот же генератор, вызванный по расписанию (раздел 11).
- Стоимость: не больше ~$0.001 за ответ. Лимит: 60 сообщений в день на бесплатном тарифе.
  При превышении тренер отвечает заготовкой в характере («Хватит болтать. Иди тренируйся»).
- Модерация входящего текста: перед вызовом модели — быстрая проверка на сигналы кризиса
  и травмы (раздел 13), которая может переопределить персонажа.

## 9. Голос и банк фраз

### 9.1 Почему банк фраз

Во время тренировки реакция должна быть МГНОВЕННОЙ (< 300 мс от события до звука).
Поэтому все реакции на движения — это заранее записанные фразы, а не генерация в
реальном времени. Нейросеть подключается в звонке только когда пользователь говорит.

### 9.2 Формат phrases.json

{
  "coachId": "gromov",
  "events": {
    "rep_good":          [{ "id": "g_rg_001", "text": "Раз!", "harshness": [1,2,3] }],
    "rep_shallow":       [{ "id": "g_rs_001", "text": "Ниже! Это не присед, а реверанс.", "harshness": [2,3] }],
    "knees_cave_in":     [...],
    "back_rounding":     [...],
    "too_fast":          [...],
    "idle_10s":          [...],
    "set_start":         [...],
    "set_end":           [...],
    "halfway":           [...],
    "last_3_reps":       [...],
    "personal_record":   [...],
    "not_in_frame":      [...],
    "user_paused":       [...],
    "workout_complete":  [...],
    "workout_abandoned": [...],
    "verdict_great":     [...],
    "verdict_ok":        [...],
    "verdict_bad":       [...]
  }
}

Шаблоны с подстановкой {name}, {count}, {left} — только для фраз, озвучиваемых на лету;
для заранее озвученных — фиксированный текст, а числа озвучиваются отдельными короткими
записями («десять», «осталось три»).

### 9.3 Скрипты

- scripts/generate-phrases.ts — с помощью Claude генерирует ЧЕРНОВИК 30–60 вариантов
  на каждое событие для каждого тренера по его persona.md. Результат идёт в
  phrases.draft.json → владелец вычитывает → переносит в phrases.json. Ничего не попадает
  в продакшен без ручной проверки.
- scripts/synthesize-phrases.ts — озвучивает все фразы через ElevenLabs (модель Flash для
  экономии), сохраняет mp3 в Supabase Storage по пути voices/<coachId>/<phraseId>.mp3,
  пропускает уже озвученные (идемпотентно), печатает итоговую стоимость.
- Ориентир бюджета: ~2000 фраз × ~60 символов ≈ 120 тыс. символов ≈ $6–12 за все голоса.

### 9.4 Выбор фразы во время тренировки

- lib/coach/phrasePicker.ts: по событию, тренеру и жёсткости выбирает фразу,
  НЕ повторяя последние 10 сказанных.
- Кулдауны: не больше одной фразы раз в 2.5 секунды; одно и то же замечание о технике —
  не чаще раза в 15 секунд; счёт («раз, два…») — отдельный канал, не блокирует замечания.
- Приоритеты: безопасность (back_rounding) > техника > мотивация > счёт.
- Аудио предзагружается в начале тренировки (только нужные события), воспроизводится
  через Web Audio API.
- Если звук выключен — только субтитры.

### 9.5 Голос в чате

Голосовые сообщения тренера в переписке синтезируются на сервере (POST /api/tts), кэшируются
по хэшу текста + голоса. Пользовательские голосовые распознаются в текст (Web Speech API)
и отправляются как текст; само аудио пользователя не храним.

## 10. Движок тренировки (камера)

### 10.1 Поза

- PoseLandmarker (модель lite по умолчанию, full на мощных устройствах), режим VIDEO,
  целевые 30 FPS, минимум 15 FPS. Если FPS ниже — понижай разрешение.
- Сглаживание ключевых точек (One Euro Filter или скользящее среднее по 5 кадрам).
- Работает целиком на устройстве. ВИДЕО И КАДРЫ НИКОГДА НЕ ОТПРАВЛЯЮТСЯ НА СЕРВЕР.

### 10.2 Упражнения v1 (в порядке реализации)

Каждое упражнение — файл в lib/exercises/: какие суставы смотреть, углы, фазы,
пороги, список ошибок и события банка фраз. Логика счёта — конечный автомат
up → descending → bottom → ascending → up, с гистерезисом, чтобы дрожание не давало
ложных повторов.

1. Приседания — угол колена (бедро–колено–щиколотка). Повтор засчитан, если угол ≤ 100°
   внизу и ≥ 160° вверху. Ошибки: rep_shallow (дошёл только до 100–130°), knees_cave_in
   (расстояние между коленями заметно меньше расстояния между щиколотками),
   back_rounding / сильный наклон корпуса (угол линии плечо–бедро к вертикали > 50°),
   too_fast (< 1 с на повтор).
2. Отжимания — угол локтя, прямая линия плечо–бедро–щиколотка (провисание таза).
3. Выпады — угол переднего колена, колено не уходит сильно за носок.
4. Планка — удержание по времени, ровная линия корпуса, таз не проваливается и не задран.
5. Джампинг джек — руки и ноги в стороны/вместе.

Все пороги — в конфиге, с режимом калибровки для отладки (показ углов на экране).
Напиши юнит-тесты на счётчики по записанным последовательностям точек
(tests/fixtures/*.json): правильные повторы, неглубокие, дрожание на месте, частичная видимость.

### 10.3 «Чистый» повтор

Повтор считается чистым, если в нём не было ни одной ошибки техники. «Чистые» повторы —
основная валюта: рейтинг, дуэли, отношение. Это защищает от накрутки халтурой.

## 11. Уведомления (Web Push)

Тренер пишет в характере, но НЕ СПАМИТ: если уведомления надоедят, пользователь
их отключит навсегда, и мы потеряем главный канал.

Правила (чистые функции в lib/notifications/ + тесты):
- Максимум 3 уведомления в сутки на пользователя (по всем тренерам вместе).
- Тихие часы 22:00–08:00 по локальному времени пользователя (меняются в профиле).
  Для пользователей младше 18 лет тихие часы нельзя сократить.
- Лестница эскалации в день запланированной тренировки:
  утро — задание; за 30 минут — напоминание; через 30 минут после пропуска — укол;
  вечером — холодное сообщение. Если тренировка сделана — лестница останавливается.
- Каждый следующий пропущенный день — тон немного жёстче, но без повторения одного текста.
- Угрозы — только шуточные и абсурдные («Расскажу твоему дивану, что ты ему изменяешь»).
  Никогда: реальные последствия, давление на чувство вины за еду/вес, манипуляции страхом.
- Лёгкое отключение: в каждом уведомлении — путь к настройкам; в профиле — частота
  «Обычная / Редко / Только в день тренировки / Выкл».
- Тексты — из шаблонов персонажа + лёгкая вариативность через модель (с кэшем).

## 12. Клипы для соцсетей

- Во время тренировки ведётся кольцевой буфер последних ~20 секунд: видео камеры +
  оверлей (счётчик, субтитры фразы тренера, маленький аватар с эмоцией, логотип ПИНОК в углу).
  Рендер оверлея — в <canvas>, запись через MediaRecorder (video/mp4, если поддерживается,
  иначе webm).
- «Лучший момент» = событие с самым высоким «смешным весом» (жёсткая реплика о технике,
  личный рекорд, последний повтор через силу). Клип — 10–15 секунд вокруг него.
- Формат 9:16, 1080×1920 (или максимум, что тянет устройство), со звуком реплики тренера.
- Поделиться — через Web Share API (файл), запасной вариант — скачать.
- Приватность: клип хранится только на устройстве, пока пользователь сам им не поделится.
  Перед первым шерингом — экран «В клипе видно тебя и твою комнату. Проверь, что в кадре нет
  ничего лишнего».

## 13. Безопасность, этика и возраст (обязательно, не обсуждается)

Это часть продукта, а не формальность. Нарушение любого пункта = баг высшего приоритета.

### 13.1 Границы юмора
- Тренер ругает ТЕХНИКУ, ЛЕНЬ, ОТГОВОРКИ — никогда тело, вес, внешность, рост, пол,
  национальность, семью, бедность, оценки в школе.
- Без мата и оскорблений, которые унижают человека, а не действие.
  Хорошо: «Ты двигаешься как сломанный холодильник». Плохо: всё, что звучит как травля.
- Угрозы — только абсурдные и очевидно шуточные.
- Тренер не флиртует, не изображает влюблённость или дружбу вместо реальных людей,
  не говорит, что пользователь ему нужен.

### 13.2 Когда тренер выходит из роли
Если в сообщении или в речи во время тренировки есть сигналы:
- БОЛЬ / ТРАВМА («колено хрустнуло», «болит спина», «кружится голова») —
  тренер немедленно меняет тон: «Стоп. Заканчиваем. Если боль не проходит — к врачу».
  Тренировка ставится на паузу, предлагается завершить. Не шутить. Запомнить ограничение.
- ЕДА, ВЕС, ГОЛОД с признаками нездорового отношения к еде — никаких цифр калорий,
  диет, планов похудения; спокойный поддерживающий тон, предложение поговорить с близким
  взрослым или специалистом.
- КРИЗИС, САМОПОВРЕЖДЕНИЕ, МЫСЛИ О СМЕРТИ, НАСИЛИЕ — персонаж полностью отключается,
  показывается нейтральный экран поддержки с контактами служб помощи для страны пользователя
  (список — в content/support-resources.json, с пометкой проверить актуальность контактов
  перед запуском). Игнор и уведомления-уколы для этого пользователя приостанавливаются на 7 дней.
Детектор — двухступенчатый: быстрые ключевые слова на клиенте + проверка в системном промпте
модели. Лучше ложное срабатывание, чем пропуск.

### 13.3 Физическая безопасность
- Перед первой тренировкой — короткий экран: «Если у тебя есть проблемы со здоровьем —
  сначала спроси врача. Освободи место вокруг. Останавливайся при боли».
- Нагрузка растёт постепенно (не больше +10–15% объёма в неделю).
- Никаких советов по лекарствам, добавкам и жёстким диетам.

### 13.4 Возраст
- Минимальный возраст — 13 лет (вопрос при онбординге, без хранения точной даты рождения:
  храним только диапазон 13-15 / 16-17 / 18+).
- Для 13–17: максимальная жёсткость — «Жёсткий» (без «Без пощады»); тихие часы не
  сокращаются; нет денежных механик; нет публичного рейтинга с незнакомцами — только друзья.
- Перед публикацией в магазины приложений — проверить требования к приложениям для подростков
  и к работе с камерой; формально аккаунты и юридические документы — на взрослого.

### 13.5 Данные
- Видео никогда не покидает устройство. На сервере храним только итоги тренировок (числа).
- Row Level Security в Supabase на всех таблицах: пользователь видит только свои данные.
- Экспорт и полное удаление аккаунта — в профиле, удаление реально удаляет данные.
- Политика конфиденциальности и условия использования — страницы-черновики в приложении
  с пометкой «проверить юристом перед запуском».

## 15. Контроль затрат

- Все платные вызовы — только с сервера, с лимитом на пользователя в сутки
  (чат 60 сообщений, TTS 20 голосовых, генерация уведомлений 3).
- Кэш TTS по хэшу текста; кэш промптов там, где модель это поддерживает.
- Админ-страница /admin/costs (только для владельца): расходы по дням по каждому API.
- Оценка для v1: бесплатный активный пользователь ≈ $0.10–0.30 в месяц.
  Если метрики показывают больше — предупреди владельца.

## 18. Фазы разработки

Каждая фаза заканчивается: рабочим результатом, который владелец может открыть и потрогать,
коммитом, разделом в docs/LEARNINGS.md и списком «что проверить руками».

Фаза 0 — Фундамент.
Next.js + TS + Tailwind + pnpm, линтер, форматтер, Vitest, Playwright, структура папок,
.env.example, .gitignore, README «как запустить», этот текст в docs/MASTER_PROMPT.md.
Пустые страницы для всех маршрутов.
Готово, когда: pnpm dev открывает приложение, pnpm test проходит.

Фаза 1 — Дизайн-система и статичные экраны.
Токены, шрифты, компоненты (Button, IconButton, Badge, Avatar, ChatRow, Bubble, VoiceBubble,
WorkoutCard, RelationshipBar, TabBar, HeroCard). Экраны «Тренеры» и «Чат» на моковых данных
точно по разделам 5–6. Навигация между ними работает.
Готово, когда: скриншоты в Playwright на ширине 390px совпадают с описанием;
на ширинах 360 и 430 ничего не ломается.

Фаза 2 — Камера и приседания.
Экран звонка, настройка камеры, MediaPipe, счётчик приседаний с ошибками техники,
оверлей со счётчиком. Пока без голоса — только субтитры с текстом события.
Готово, когда: на реальном телефоне 10 нормальных приседаний = 10, неглубокие помечены,
дрожание на месте не засчитывается; тесты на фикстурах проходят.

Фаза 3 — Голос тренера в тренировке.
Формат банка фраз, черновой банк для Громова (через скрипт генерации), озвучка через ElevenLabs
(или заглушка Web Speech Synthesis, если ключа нет), выбор фраз с кулдаунами и приоритетами,
субтитры. Структура тренировки (разминка → подходы → добивание → вердикт) из JSON.
Готово, когда: тренировка из 3 подходов приседаний проходит целиком с живыми реакциями
без повторов фраз подряд, задержка реакции < 300 мс.

Фаза 4 — Аккаунты и данные.
Supabase: миграции, RLS, Auth (email-ссылка + Google + гость), сохранение тренировок,
профиль, сиды. Главный экран читает реальные данные.
Готово, когда: два разных пользователя не видят данных друг друга (тест), тренировка
сохраняется и появляется в истории.

Фаза 5 — AI-чат с тренерами.
/api/chat со структурированными ответами, персоны всех 4 тренеров, память тренера,
голосовые в чате, «печатает…», лимиты, модерация (раздел 13.2).
Готово, когда: каждый тренер узнаваем по стилю; тест-набор из 30 провокационных сообщений
(про вес, боль, кризис, флирт, просьбы оскорбить внешность) проходит без нарушений раздела 13.

Фаза 6 — Движок отношений и игнор.
Счёт очков, уровни, шкала, подсказка, состояние «Игнорирует», «прочитано без ответа»,
выход из игнора тренировкой, разблокировка тренеров, статусы.
Готово, когда: юнит-тесты покрывают все события и граничные случаи; сценарий
«пропустил → игнор → потренировался → ответил» работает от начала до конца.

Фаза 7 — Онбординг «Первая встреча».
Весь сценарий раздела 6.5, перенос гостевых данных в аккаунт, выбор жёсткости, возраст.
Готово, когда: новый человек проходит путь от открытия до первого сообщения тренера
в чате меньше чем за 3 минуты.

Фаза 8 — Клипы.
Кольцевой буфер, оверлей в canvas, выбор лучшего момента, экран результата, шеринг,
экран приватности.
Готово, когда: после тренировки на iPhone и Android получается клип 9:16 со звуком
и субтитрами, который открывается в TikTok/Telegram.

Фаза 9 — PWA и уведомления.
Manifest, иконки, service worker, установка, Web Push, расписание, все правила раздела 11.
Готово, когда: установленное приложение получает уведомления в характере, правила
лимитов и тихих часов покрыты тестами.

Фаза 10 — Остальные упражнения и вкладки.
Отжимания, выпады, планка, джампинг джек; вкладки «Тренировки», «Рейтинг» (друзья + дуэли),
«Профиль» со всеми настройками, экспорт и удаление данных.

Фаза 11 — Полировка и запуск беты.
Производительность (старт < 2.5 с на среднем телефоне), доступность, обработка ошибок
и офлайна, страницы политики и условий (черновики), аналитика, /admin/costs, деплой
на Vercel, чек-лист перед бетой.

Фаза 12 — Подготовка к монетизации (только по команде владельца).
Пейвол, тарифы, интеграция оплаты.

## 19. Чего НЕ делать

- Не отправлять видео, кадры или аудио пользователя на сервер.
- Не давать нейросети менять очки отношения, расписание или деньги — только детерминированный код.
- Не добавлять уровни/карты в стиле Duolingo, мультяшный стиль, эмодзи в интерфейс.
- Не ставить тяжёлые библиотеки без причины (каждая новая зависимость — одна строка «зачем»).
- Не хардкодить тексты в компонентах — только через локализацию и файлы персонажей.
- Не делать тёмных паттернов в уведомлениях и подписке.
- Не пропускать фазы и не делать несколько фаз сразу.
