# Учебник: как устроен ПИНОК

Это не справочник, а рассказ «что происходит, когда…». Читай по порядку — так проще понять,
как кусочки складываются в приложение. Каждый пункт указывает, где в папках искать код.

---

## 1. Что происходит, когда ты нажимаешь «Позвонить»

```
Нажал  ->  создаётся запись о тренировке  ->  открывается экран звонка (/call/<id>)
                                                  |
   камера  ->  MediaPipe (нейросеть в браузере)  ->  33 точки тела  ->  углы суставов
                                                  |
              счётчик повторений (конечный автомат)  ->  «чистый» повтор или ошибка
                                                  |
                    «режиссёр» выбирает фразу  ->  голос + субтитр + эмоция аватара
                                                  |
                        конец  ->  очки отношения, вердикт, клип, экран результата
```

- **Запись о тренировке:** `lib/workout/startSession.ts`. План — это JSON (`content/plans/*.json`),
  а не код: добавить тренировку = добавить файл.
- **Поза:** `lib/pose/` — MediaPipe PoseLandmarker работает **в браузере**, поэтому видео никуда не уходит.
  Углы считаются по 3D-точкам (`worldLandmarks`), чтобы приседания спереди измерялись честно.
  Дрожание сглаживает фильтр «One Euro».
- **Счётчик повторений:** `lib/exercises/repMachine.ts` — конечный автомат
  «вверху → вниз → внизу → вверх». Пороги (например, колено ≤ 100° внизу) лежат в конфиге упражнения,
  а у порогов есть «гистерезис»: чтобы дрожание на границе не давало лишних повторов.
- **Режиссёр тренера:** `lib/workout/director.ts` превращает события («повтор», «колени внутрь»)
  в реплику. Фразы берёт из банка (`content/coaches/*/phrases.json`) через `lib/coach/phrasePicker.ts`:
  не повторяет последние 10, держит паузу между репликами, ошибки техники важнее похвалы.
- **Голос:** `lib/speech/coachVoice.ts` — готовые озвучки (если есть), иначе голос браузера.
  Из-за заготовок реакция мгновенная: никто не ждёт нейросеть посреди приседания.
- **Симулятор:** `lib/pose/simulator.ts` «приседает» цифрами. Благодаря ему тесты и демо работают без камеры.

## 2. Что происходит, когда ты пишешь тренеру

```
Текст  ->  детектор тяжёлых тем (на телефоне)
              | боль / еда / кризис / лекарства -> проверенный текст приложения (нейросеть не зовём)
              | иначе
           тренер игнорирует?  -> «прочитано», ответа нет
              | иначе
           /api/chat (сервер)  ->  Anthropic (если есть ключ и лимит)  ->  проверка ответа
              | не вышло / нет ключа / нарушены правила
           заготовленная реплика тренера по смыслу сообщения
```

- **Клиент:** `lib/chat/respond.ts` — вся последовательность. `lib/chat/memory.ts` — «память тренера»
  (до 10 коротких фактов, без личных данных).
- **Сервер:** `app/api/chat/route.ts` → `lib/server/chat.ts`. Нейросеть отвечает строгим JSON
  (сообщения, эмоция, действие, флаг безопасности). Ответ проверяется (`lib/chat/schema.ts`,
  `lib/safety/guard.ts`); если плохой — одна повторная попытка, потом заготовка.
- **Заготовки:** `content/coaches/*/scripted.json`, смысл сообщения определяет `lib/coach/intent.ts`.
- **Ключ Anthropic** лежит только на сервере. Лимиты (60 ответов в день на человека и общий потолок в
  долларах) — в `lib/server/usage.ts`.

## 3. Отношения и игнор — это обычная арифметика

- Очки 0–100 → уровни «Презирает / Терпит / Уважает / Гордится» (`lib/relationship/`).
- За тренировку плюс, за пропуск минус; «буфер» не даёт уровню прыгать вниз от мелочи.
- Пропустил плановую тренировку → игнор на 12 часов (`lib/game/appOpen.ts`, `lib/game/ignoring.ts`).
  Игнор снимает **только** выполненная тренировка. Нейросеть тут вообще не участвует.
- Всё это считается при открытии приложения и раз в минуту, пока оно открыто, — по времени, которое
  прошло. Поэтому «пока тебя не было» работает без сервера.

## 4. Данные живут в телефоне

- `lib/data/repository.ts` — интерфейс «куда класть данные». `lib/data/dexieRepository.ts` — как это
  делается сейчас (IndexedDB через Dexie). Экраны знают только интерфейс, поэтому позже можно
  заменить хранилище на облако, не переписывая экраны.
- Экспорт и полное удаление — «Профиль». Демо-данные — `lib/data/demo.ts`.

## 5. Безопасность — два рубежа

1. **До нейросети** (`lib/safety/detector.ts`): ключевые слова про кризис, еду, боль, лекарства.
   Тут перестраховка осознанная: лучше лишний раз спросить «как ты?», чем пропустить беду.
2. **После нейросети** (`lib/safety/guard.ts`): ответ без оскорблений тела, флирта, мата, советов по
   лекарствам и «терпи боль». Нарушение не показывается, вместо него — заготовка.

Возраст: до 18 лет жёсткость не выше «Жёсткий» (`lib/safety/age.ts` — это правило хранилища, а не
настройка). Проверки: `tests/safety/` — 31 провокация и аудит всех фраз тренеров.

## 6. Уведомления без спама

- Правила — чистые функции в `lib/notifications/rules.ts`: не больше 3 в день, тихие часы, лестница
  «утро → напоминание → укол → вечер», тон растёт при пропусках.
- Пока приложение живо в фоне: системное уведомление через service worker (`public/sw.js`).
- При закрытом приложении: необязательный Web Push (`lib/server/push.ts`, `/api/push/*`).

## 7. Клипы

`lib/clips/` — во время тренировки на скрытом холсте 9:16 рисуется видео + оверлей, MediaRecorder пишет
отрезки по ~15 секунд, остаётся отрезок с самым «смешным» моментом. Перед первым «Поделиться»
показывается экран «Проверь кадр».

## 8. Рейтинг и дуэли без сервера

Всё нужное лежит в ссылке (`lib/social/links.ts`). Друг открывает ссылку — и попадает в твою таблицу.
Недостаток: цифры в ссылке можно подделать. Для дружеской игры хватает, для призов нужен сервер.

## Три сторожа качества

- `pnpm lint` — читает код и ищет опасные места.
- `pnpm test` (Vitest, ≈ 600 проверок) — логика без браузера: счётчики, отношения, правила уведомлений, безопасность.
- `pnpm test:e2e` (Playwright) — настоящий браузер с поддельной камерой ходит по экранам: знакомство,
  звонок, результат, клип, вкладки, дуэль между двумя «людьми».

## Словарик

- **PWA** — сайт, который ставится как приложение.
- **IndexedDB** — база данных внутри браузера.
- **Service worker** — «помощник» сайта, работающий в фоне: кэш и уведомления.
- **Конечный автомат** — программа, у которой есть чёткие «состояния» и правила переходов.
- **Гистерезис** — разные пороги «туда» и «обратно», чтобы значение не мигало на границе.
- **Web Push** — уведомления, которые приходят, даже когда сайт закрыт.
- **VAPID** — пара ключей, которой сервер доказывает push-сервису, что это именно он.
